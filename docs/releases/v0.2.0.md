# Chorono v0.2.0 — Large-scene performance and resource management

Released 8 November 2026. [Türkçe](../tr/releases/v0.2.0.md) ·
[Validation and limitations](v0.2.0-validation.md) · [Changelog](../../CHANGELOG.md)

Chorono v0.2.0 makes large 2D animation projects use a bounded working set of
rendering surfaces and media resources, improves editing responsiveness, and fixes
missing descendants under Solo parents. It also brings the accumulated scripting,
audio, spline, timeline and onboarding work into `main`.

## Large-scene rendering and editing

- **Scene and track indexes** replace repeated full-scene lookups in rendering,
  transform resolution and timeline access.
- **Dependency-safe viewport culling** skips offscreen paint while preserving
  masks, effect padding and helper sources required by visible content.
- **Static-group LOD** caches bounded viewport proxies for suitable groups. Source
  layers remain editable. Final PNG and image-sequence output renders the original
  full composition rather than the viewport's LOD proxy or visible-area crop.
- **Shared scratch-surface pools** reuse mask/effect canvases. Region-of-interest
  rendering reduces temporary backing pixels; unsupported or uncertain bounds use
  conservative rendering instead of silently losing content.
- **Virtualized UI** bounds mounted layer, timeline, dope-sheet and asset rows.
  Dense keyframe tracks use compact glyphs while preserving selection, keyboard
  navigation and access to individual source keys.
- **Frame scheduling** coalesces obsolete viewport/runtime work and avoids
  accumulating evaluations behind the latest requested frame.

## Resources and diagnostics

- A shared **512 MiB managed-resource policy** coordinates participating owners,
  including rendering surfaces, LOD, media preparation, decoded audio, fonts and
  output jobs. Per-owner policies and pin/release lifetimes remain explicit.
- Bounded queues, cancellation, deadlines and stale-result checks apply across
  preparation, import, encode, save and document replacement flows.
- Image/video residency follows the current frame's visible dependencies; audio
  uses timeline demand, and fonts/source URLs have dedicated ownership adapters.
  Undo retains serializable source data rather than native DOM/GPU handles.
- The English **Resources & Performance** dock reports tracked resources,
  media, CPU/GPU workload, paint/culling/LOD counts, budgets, pending jobs and
  browser-memory estimates with their measurement scope.
- The viewport shows **Last draw … ms · Heap …**. It updates after drawing,
  has no idle polling loop, and stays outside exported pixels. FPS would be
  misleading for an on-demand canvas.
- Paused resource monitors immediately drop cached identities of replaced
  projects, rather than retaining an old scene graph until polling resumes.

Managed bytes and browser heap are different scopes. This policy is not a hard
limit on all browser, decoder, GPU-driver or OS RAM.

## Safer import, export and persistence lifetimes

- Bounded binary/text readers and container validation cover ZIP/dotLottie, GIF,
  SVG/Lottie/scene documents, font input and supported native-media admission.
- Supported image dimensions and WAV PCM sizes are checked before expensive
  native work. Opaque codecs retain explicitly documented policy estimates.
- Output ownership covers raster/image sequence ZIP, offline WAV, portable
  projects, JSON/HTML/runtime/SVG, clipboard, MCP replies and file persistence.
- Buffers and pins live until the actual asynchronous consumer settles. Cancelled
  or stale work does not publish a late result; failed cleanup remains visible.
- Autosave and version-file writes coalesce pending snapshots with finite queues
  instead of retaining a new dense serialization for every edit.

This release improves the resource safety of existing exporters. The separate
**Export E0** project will establish viewport/render-preview/export consistency
fixtures and drive later resolution, color and quality improvements.

## Scene Explorer and Timeline fixes

- Soloing a parent now includes its descendants in both panels, even when that
  parent is not a member of the selected timeline. Hidden/inactive child tracks
  remain editable; explicit panel filters and timeline membership still apply.
- **Expand subtree / Collapse subtree** open or close the selected branches,
  including nested groups, without changing scene data.
- **Show subtree / Hide subtree** affect selected roots and every descendant in
  one undoable command. Undo restores each child's previous mixed visibility.
- The four actions are available for a single selected parent, multi-selection
  and the context menu. Overlapping selections are deduplicated.

## Animation authoring and usability

- Expanded scene/layer snapshots and safe patches, spline and particle handles,
  interaction definitions and native audio clip operations in the scripting API.
- Audio inspector and timeline editing for trim/split, gain/envelopes and clip
  selection, with shared PCM ownership for playback, waveforms and offline output.
- Spline placement, point editing, transformed bounds, picking and path-trimming
  fixes; timeline cloning, keyframe operations and independent-animation fixes.
- Refreshed welcome/startup UI, English interface copy and local setup/examples.
- Maintainer documentation records SOLID responsibilities, module ownership,
  source/cache separation, lifecycle contracts and the current 2D/2.5D roadmap.
- The current `main` CI, security reporting and community contribution templates
  are preserved in the release integration.

## Validation

The implementation acceptance ran **262 test files / 2,093 tests**, typechecking,
MCP/Next builds and a 31-check evidence audit. The original Four Seasons fixture
(4,079 layers, 42,512 keys, 48 seconds) completed ten full plays in 490 seconds:

| Measurement | Observed result |
| --- | ---: |
| Managed-resource peak / policy | 46.15 / 512 MiB |
| JavaScript heap peak / guard | 107.61 / 768 MiB |
| Final JavaScript heap | 40.33 MiB |
| Synchronous viewport draw p50 / p95 | 30.7 / 47.5 ms |
| Whole-page RAF interval p50 / p95 | 33.4 / 66.7 ms |
| Extra canvas registrations per cycle | 0 |

Fifty independently committed UI edits, undo/redo, seeking, panning/zooming and
project close/reopen were checked. Actual scene downloads matched the original
bytes. Final unmount returned managed charges and source references to zero.
Native A/V and LOD PNG/ZIP checks passed within their documented capabilities.

These are measurements of one fixture and environment, not universal FPS or RAM
guarantees. [The validation report](v0.2.0-validation.md) retains CPU variability,
native-memory limits, bundle scope and the final release checks.

## Install this release

Requires Node.js 20+, npm, Git and a modern browser:

```sh
git clone --branch v0.2.0 --depth 1 https://github.com/codie1982/chorono-editor.git
cd chorono-editor
npm ci
npm run cli:build
npm run chorono -- setup
npm run chorono -- start --background --open
```

Choose **MCP → Connect this editor** in the browser, reload your agent's MCP
connection, then run `npm run chorono -- doctor`.

The editor package version is `0.2.0`; the CLI source remains independently
versioned at `@codie1982/chorono@0.2.0`. This is a GitHub release. The root editor
stays private, and no npm registry publication is implied.
